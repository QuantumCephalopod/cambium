2. Purpose and character of the website

sss.saarland is an artistic research website.

One part of the website, “Crawlerbait”, studies and visualises how people, browsers, bots, crawlers and other technical systems interact with a publicly accessible website. Crawlerbait turns actually observed technical interactions into a digital artwork with pseudonymous “Beings”, “Baits” and visual properties derived from them.

Crawlerbait is not used to establish people's civil identities or to assess people for legal, economic or comparably significant decisions.

3. General technical operation of the website

GitHub Pages and Cloudflare in particular are used to provide the website technically.

When the website is accessed, technically necessary connection and request data are processed. These may include in particular:

  • IP address;
  • time;
  • requested resource;
  • HTTP method and response status;
  • User-Agent and other technical connection data.

This processing serves the delivery of the website, its stability, technical observability and security.

The legal basis is Article 6(1)(f) GDPR. The legitimate interest is the secure, functional and traceable operation of the website.

GitHub expressly states that visitors' IP addresses are logged and stored for security purposes on GitHub Pages. The respective providers' privacy information also applies to processing on the providers' side.

4. Crawlerbait — artistic research processing

4.1 Observed technical events

Crawlerbait obtains technical HTTP events from Cloudflare Analytics.

The provider may supply in particular the following technical characteristics:

  • time;
  • IP address;
  • User-Agent;
  • request path;
  • HTTP method;
  • HTTP status;
  • other technical characteristics of the request, connection, client and delivery.

Not all provider characteristics are stored or published as readable data.

4.2 Query strings

Crawlerbait does not request the query part of a URL, meaning the part after “?”.

The Cloudflare field clientRequestQuery is neither stored as a public trace nor processed into a Being's artistic DNA.

4.3 Private Recognition

The IP address and full User-Agent are processed within the private Recognition boundary to the extent necessary to associate recurring interactions of the same technical relation with a stable pseudonymous Being.

In doing so, Crawlerbait persists neither the plaintext IP address nor the Network Recognition value derived internally from it as a public trace. The full User-Agent is likewise not stored as a current public Being attribute.

The public Being ID is separate from this private Recognition material and serves continuity within the artwork.

Pseudonymisation does not mean anonymisation here. Where additional information could make it possible to relate the data to a person, the data remain personal data within the meaning of the GDPR.

4.4 Request paths / Baits

Not every requested path is published in plaintext.

Crawlerbait's own public apertures may remain readable as such. Other request paths, or paths not required to be published readably, are converted into a stable opaque Bait ID through a keyed one-way transformation before public storage.

This is intended in particular to prevent email addresses, tokens, IDs, secrets or other arbitrary strings that happen to be contained in paths from appearing as a readable public request log.

4.5 Phenotype / DNA

Other technical provider characteristics may influence a Being's visual appearance.

These values are not stored as a public profile table for this purpose. They are condensed into an opaque Phenotype/DNA signature through keyed irreversible interference.

For example, colour, texture, shape, movement or other artistic properties may be derived from this signature.

The underlying readable provider values are not persisted as current public Crawlerbait attributes.

5. Which Crawlerbait data may be publicly visible

In particular, the following may be publicly visible:

  • an opaque Being ID;
  • a public path designation belonging to Crawlerbait or an opaque Bait ID;
  • the time of an Encounter;
  • HTTP method;
  • HTTP status;
  • derived Being Kind;
  • opaque Genome/Phenotype signal;
  • artistic visualisations generated from it;
  • relationships between Being, Bait and observed time.

In particular, the following are not intended as current public Crawlerbait attributes:

  • plaintext IP address;
  • internal IP/Network Recognition value;
  • full User-Agent;
  • query string;
  • readable auxiliary raw Cloudflare attributes;
  • arbitrary third-party request paths, or request paths not required to be published readably, in plaintext.

The expressly public pseudonymous components of Crawlerbait are intentionally accessible to everyone. Third parties may copy, archive or further process publicly accessible content.

6. Legal basis and legitimate interests

Crawlerbait processing is based on Article 6(1)(f) GDPR.

The legitimate interests include in particular:

  • the secure and traceable technical operation of the website;
  • artistic engagement with actual interactions on the public web;
  • research observation of recurring patterns of interaction;
  • preserving the artwork's longitudinal form, which requires recurring pseudonymous Beings.

The interests and rights of data subjects are taken into account in particular through data minimisation, separation of Recognition from public representation, pseudonymisation, irreversible condensation of raw technical characteristics, exclusion of query strings and the Path Membrane.

7. No automated decisions with legal effects

Being Kinds, DNA, Phenotype and other Crawlerbait classifications serve solely the artwork's artistic representation and technical structure.

No decisions are made on their basis that produce legal effects concerning a natural person or similarly significantly affect that person.

9. Cookies, browser tracking and local storage

At its current technical state, this website does not deploy its own Google Analytics or Matomo trackers.

The current website code provides no tracking mechanism of its own through document.cookie, localStorage or sessionStorage.

If storage of, or access to, information on a user's device that is not technically necessary is introduced in future, it will be examined before or alongside that change whether consent under section 25 TDDDG or another legal basis is required.

10. Retention periods and criteria

10.1 Private raw Crawlerbait measurement

Crawlerbait processes IP addresses, full User-Agents and other readable provider values only within the Capture/Recognition procedure, to the extent necessary for the respective transformation. Crawlerbait does not store them as current readable public traces of the artwork.

This is distinct from any storage on the providers' side at Cloudflare or GitHub under their respective product, security and retention rules.

10.2 Public pseudonymous artwork data

The metabolised pseudonymous Crawlerbait data are stored for as long as they are needed for the artwork's ongoing longitudinal structure, the continuity of pseudonymous Beings or the traceable representation of observed interactions.

There is no fixed calendar-based deletion period for these data.

Data are removed or further anonymised if the underlying purpose ceases to apply, the data are no longer required for the artwork's ongoing structure, or a legally enforceable claim to erasure or objection exists and no overriding legal grounds or compelling legitimate grounds stand in the way.

11. Historical Git data

During its development, Crawlerbait was narrowed from a data protection perspective. Earlier public Git history temporarily contained more extensive technical request data than the current system.

On 2 October 2026, all public branch/tag references controlled by the operator in the authoritative repository and the operated public fork were replaced through a cleaned Git history rewrite. The currently controlled branches and tags no longer reference the removed historical request carriers.

GitHub also manages its own pull request references, cached views and server-side Git objects. For this remaining provider-side cleanup, GitHub Support was asked on 2 October 2026 to dereference the affected pull request refs, remove cached views and perform server-side garbage collection. Until GitHub confirms this cleanup, some old Git objects may technically remain accessible through direct object identifiers, even though the controlled public branches or tags no longer reference them.

Independent copies or clones made by third parties before the cleanup cannot subsequently be deleted remotely by the operator.

12. Provision of data

Merely visiting the website entails no contractual obligation to provide data separately to Crawlerbait.

However, technical connection data arise automatically when communicating with a web server. Without the technical data necessary for network communication, an HTTP request cannot be transmitted and answered.

No registration or provision of a civil name is required for Crawlerbait.
