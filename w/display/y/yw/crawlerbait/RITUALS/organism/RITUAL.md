# CRAWLERBAIT SITE-HOLON RITUAL — local public body

Crawlerbait is an autonomous public interlocutor inside Display Population. It is a machine-facing habitat and a human-visible observatory of the same habitat. Its job is not to block crawlers. Its job is to let ordinary public-web contact leave bounded traces that can alter later static encounter conditions.

## Sensor membrane — Cloudflare observes; crawler requests stay static

Crawler requests must terminate on the ordinary static Pages/CDN surface. **No `/bait/*`, grown route, or ordinary Crawlerbait read is routed through a Worker merely to detect presence.**

Cloudflare analytics is a provider-constrained observation aperture. A periodic tide may query bounded aggregated request telemetry after the requests have already happened. The provider observation is evidence of HTTP contact, not proof of actor identity or intent.

Current v1 sensor contract is deliberately small and based only on all-plan dimensions/filters already witnessed in Cloudflare documentation:

- real client request source (`requestSource: eyeball`);
- `404` response pressure;
- requested path;
- claimed User-Agent grouped with that path;
- adaptive-sampling witness when exposed.

Do not invent country/ASN/bot-verification fields until the live token/schema has actually witnessed them for this zone.

## Tide — bounded mechanical sedimentation

The tide is periodic, not real-time. The current target cadence is every six hours; the first armed tide may look back at most 24 hours. One tide performs exactly one bounded observation→projection pass.

The deterministic v1 growth gate is canonical in `bait/policy.json`:

- only safe extensionless page-like paths are admitted;
- reserved host/crawlerbait paths are excluded;
- a path must accumulate at least the configured repeated `404` pressure before embodiment;
- at most the configured number of new routes may grow in one tide;
- total grown routes and unresolved candidates are capped;
- User-Agent strings are treated as self-claimed and spoofable;
- raw IP addresses and raw User-Agent strings are never persisted into the public body;
- unknown/variant User-Agents are represented by a bounded family token plus a one-way short digest.

Changing these gates is a ritual/policy mutation, not something traffic may request for itself.

The mechanical action may execute the already-earned policy. It may not reinterpret a path semantically, infer crawler motives, or promote bait routes into CCCC anatomy.

## Local tissue

- `bait/policy.json` — the bounded deterministic admission/growth contract consumed by the tide implementation.
- `bait/state.json` — current local sediment of admitted safe pressure, unresolved candidates and grown route receipts. It is current experiment state, not raw Cloudflare logs.
- `projection.json` — bounded Display-facing projection derived from current bait state.
- `public/` — generated static outward surface. It is rebuilt deterministically from current admitted bait state; crawler reads of this tree execute no site code.
- `tide.py` — local mechanical implementation of the already-earned sensor/growth contract.

Raw provider telemetry is not copied into the repository. Only bounded aggregates that survive the admission contract enter `bait/state.json`.

## Identity-owned public routes

A grown route is an identity-owned public aperture of Crawlerbait, not a site-space address and not a Display vertex. `/login`, `/admin`, or any later bait route therefore lives **inside the interlocutor's public behavior** even though the HTTP path is rooted at the domain.

Crawlerbait's public route tree may be projected into the Pages artifact through Display's generic site-holon static-surface hook. The generic hook may copy bytes and reject collisions; it must not know what `/login` means or special-case `organism:crawlerbait`.

Current route embodiment uses directory indexes (`public/login/index.html` for observed `/login`). A provider may therefore redirect the slashless request to `/login/`; that transport behavior is not interpreted as a semantic failure. The receipt must continue to name the originally observed path.

## Receipt semantics

A receipt says only what the sensor actually established. Current public receipts may expose:

- originally requested safe path;
- bounded aggregate count of prior observed 404 pressure;
- observation/materialization times at tide resolution;
- whether adaptive sampling was witnessed;
- bounded claimed User-Agent family token and one-way signature digest.

Never call this data authenticated identity, credentials, a unique individual, or proof of a specific company. A claimed `GPTBot` string means only that the grouped request presented that User-Agent unless stronger provider verification is separately earned later.

4. raw IP addresses and raw User-Agent strings are absent from committed/public state;

6. site-holon identity and all local bytes survive lawful global remounting;

8. the generic public-static hook rejects output collisions and reserved artifact paths;
9. the exact generated artifact passes the existing Display structural/address/browser witnesses plus the local tide self-test;
10. the scheduled tide produces no repository mutation when no safe pressure is admitted.
