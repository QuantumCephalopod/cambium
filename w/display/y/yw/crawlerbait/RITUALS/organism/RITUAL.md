# CRAWLERBAIT SITE-HOLON RITUAL — local root

`crawlerbait` is one independently re-enterable site-holon encountered through Display Population.

Global placement is environment:

`site-space:w ⟦ crawlerbait:ε ⟧`

Its current root constitution is:

- `w · Baits / CREATE` — durable same-type crawlerbait bodies;
- `x · Traces / COPY` — continuing observed path × claimed-client evidence;
- `z · Membrane / CONTROL` — sensing/public/credential boundary;
- `y · Tide / CULTIVATE` — periodic passive reacquisition and regrowth.

`INDEX.yaml` names these four current vertex wholes and root `_cambium.yaml` carries their exact `4V / 6E / 4F / 1T` closure.

## w · Baits — same-type population membrane

`w` is not a bag of renderer assets. It is exclusively the Bait population.

Crossing the vertex restarts a separate same-type geometric address space:

`crawlerbait:w ⟦ bait-space:ε ⟧`

Physical bait placement mirrors Display Population's same-type rule. A bait at local bait-space address `<a>` is carried at:

`crawlerbait/w/w<a>/bait.json`

The outer `w` is the Crawlerbait CREATE vertex and is stripped at the bait-space membrane. The repeated leading `w` on the physical carrier marks entry into bait-space, just as Display's Population carrier repeats its own membrane prefix.

One exact raw bait-space address may contain one bait. Bait identity is the observed HTTP path, not its current bait-space placement. Placement is deterministic nonsemantic geometry derived from stable path identity; when two identities share an address prefix, the shared locus differentiates deeper until exact occupancy is unique. A later collision may therefore deepen placement without creating a new bait identity.

Each bait locus contains at most its `bait.json` body. No renderer, stylesheet, public secretion or tide machinery belongs in `w`.

## x · Traces — evidence continuity

`x/state.json` preserves every positive-count 404 group returned by the chosen Cloudflare sensor, accumulated by observed path and claimed User-Agent signature.

There is deliberately no relevance filter, recurrence threshold, ranking, shortlist or route/signature budget. User-Agent strings are client claims, not authenticated identities. The current sensor does not request client IP addresses.

The bait body and trace ledger are related but not identical:
- `w` answers *what bait exists and where it lives in bait-space*;
- `x` answers *what was observed about that bait through time*.

## z · Membrane — bounded sensing and outward embodiment

`z` owns the site-holon membrane implementation:
- `policy.json` — provider-window mechanics only;
- `projection.json` — derived Display-facing view;
- `render.js` / `style.css` — Crawlerbait phenomenology;
- `public/` — generated crawler-facing static secretion.

Crawlerbait never writes public bait pages at global root paths such as `/login` or `/papers`. Every outward route remains under `/crawlerbait/*`.

Observed path is data. Public representation is a separate membrane consequence.

When an observed path can be mirrored as ordinary static components, the public receipt uses `/crawlerbait/bait/<observed-shape>/`. Otherwise it uses `/crawlerbait/receipt/<stable-id>/`. Representation differences never erase the observation.

## y · Tide — periodic growth

`y/tide.py` performs ordinary incremental sensing.

`y/backfill.py` performs an explicit full retained-history reseed.

Canonical motion:

`Cloudflare 404 groups → x Traces → w Baits → z Membrane`

The tide is periodic rather than request-triggered. Ordinary crawler reads remain static CDN/Pages traffic and invoke no Worker merely to announce presence.

A full-history reseed is also the canonical structural migration into the current bait-space generation. It rebuilds `x`, then regenerates `w` and `z` mechanically from that complete state.

## address-space invariants

The same-type population law is intentionally the same family of relation used by Display Population:
- occupant identity is independent of address;
- exact raw addresses exclude pile-up;
- pressure differentiates a colliding address deeper rather than inventing a named bucket;
- address is geometric genealogy, not a category label;
- projection/visualization may read the actual address tree instead of reconstructing synthetic point placement.

This is why `/login`, `/.env`, `/wp-json`, etc. are never directory taxonomy inside the canonical body. They remain bait identity fields in `bait.json`; the physical tree is recursive bait-space.

## closure

A Crawlerbait change closes only when:
1. root `w/x/z/y` still realize Baits / Traces / Membrane / Tide and root `4V/6E/4F/1T` remains closed;
2. `w` contains only addressed bait bodies;
3. every sensed positive-count 404 group remains in `x` without heuristic relevance filtering;
4. all public/static/renderer tissue remains in `z`, never mixed into bait-space;
5. tide/backfill remain in `y`;
6. Cloudflare credentials never enter repository/public bytes;
7. ordinary crawler reads remain static;
8. bait identity survives bait-space relocation/deepening;
9. generated public files remain wholly under `/crawlerbait/*`;
10. exact build/address/tetrahedral/public witnesses pass.

Compression: **Baits are bodies, Traces are memory, Membrane is the bounded skin, Tide is growth. `crawlerbait:w` opens a real same-type bait-space, so the background tetrahedron can eventually render the actual anatomy rather than a synthetic scatterplot.**
